# L4 ハザードの表示段階

この自作レイヤーは表示の重複と中間倍率の負荷を避けるため、現在のレイヤー一覧には登録していません。利用者は本家SVGMapの「重ねるハザードマップALL」を使用します。以下は、自作レイヤーを再利用する場合のために残した実装記録です。

| SVGMap scale | 表示 | 理由 |
| --- | --- | --- |
| 10 未満 | 全国の軽量ベクター概要 | 表示対象が小さい |
| 10–15 | 都道府県ごとの分割 WebP 画像 | 県全域の巨大な SVG path を毎回描き直さない |
| 15–70 | 画面内の市区町村ごとの約 50 m 相当の形状 | 地理範囲で読み込みを絞る |
| 70 以上 | 元データの詳細区域 | 狭い表示範囲でのみ元データを描く |

岡山県（33）のみ、倍率 15–30 は従来の県分割画像、倍率 30–90 は元の区域形状から生成した高精細 WebP タイルを使用します。倍率 90 で元データの詳細 SVG に切り替えるため、岡山県では市区町村 SVG の中間段階を読み込みません。詳細段階は画像や簡略化した形状ではなく、元の区域 SVG を表示します。元のポリゴン座標は変えず、公開時に太すぎる輪郭線だけ約1ピクセルへ細くします。タイルも同じ線幅で生成し、境目の見た目を揃えます。他県は従来どおり倍率 15 で市区町村 SVG に切り替わります。画像の画素密度は県ごとに異なるため、この構成を全国へ一律適用しないでください。

画像は `map/layers/hazard` の元の区域形状から生成した lossless WebP で、種類別にオン・オフできます。広域画像は `svgmapAppLayers/appLayers/svg3-bosai/hazard-raster-tiles`、岡山県の高精細タイルは `svgmapAppLayers/appLayers/svg3-bosai/hazard-detail-tiles` に保存します。後者は96 px／SVGMap座標単位で生成し、空白を除く157枚・約6 MiBです。元データを更新したら `npm run data:hazard-raster-tiles` と `npm run data:hazard-detail-tiles` を実行し、生成物をソース更新と一緒にコミットしてください。`npm test` は元データと画像の整合性を確認します。

公開用 `pref/*.svg` は `npm run assets:prepare` が変換します。元の県全域SVGと旧画像概要はリポジトリ内に残しますが、公開配布には含めません。詳細区域が揃うまでは画像を表示し、白地になる切替を避けます。画像だけを表示する段階では、SVG文書の読込完了を繰り返しポーリングしません。

岡山周辺のローカル Chromium 計測では、旧県全域SVGの倍率34.9での path 描画約 1.1–1.6 秒に対し、市区町村方式では約 0.05–0.12 秒でした。これは特定の端末・地点の計測であり、全地点の体感速度を保証する値ではありません。

今回の倍率 16 付近の試験では、表示範囲に読み込まれる市区町村 SVG が 18 文書・path データ約 1.76 MiB から、岡山県の切り替え延期後は 5 文書・約 0.25 MiB に減りました。倍率 32 付近では高精細タイル40件を取得し、元の岡山県市区町村 SVG は読み込んでいません。倍率80・89では高精細画像のみ、倍率100では元の区域SVGを読み込んで画像を非表示にすることをローカル Chromium で確認しました。周辺県の文書は従来の倍率で読み込まれます。画質と操作感は公開環境と利用端末でも確認が必要です。
